The problem

Today's agents start from zero.

Every task, they reason it out from scratch. JSON tool-agents pay full price on every run. Code-mode agents are cheaper - but stateless per session.

Even "memory" add-ons just store text to re-read - the model still re-reasons every time.

Cost per task stays flat. Nothing executable accumulates.

The platform

An eternal, living Lisp image with one door.

zeno is the whole thing - environment + workflow + agent orchestration, expressed in Lisp. Not a kernel you build on top of; the runtime itself.

Instead of N brittle tools, an agent calls one: eval over a live image. Every action - even spawning other agents - is code.

The shape

The image lives forever. Agents are episodes.

An agent has a finite context window - it can't live forever. So the eternal, self-persisting core is a living Lisp image; agents (Claude Code and others) are bounded workers it spawns on demand.

A costly model decides once. Its decision is code - which dispatches cheap execution and cheap verification.

The technical core

A workflow is code that calls agents.

A workflow is plain Lisp. It spawns agents - each with a connected environment: a single eval door into the live image. Through it an agent calls a curated set of environment functions - and can extend the environment itself, gated by tests.

Every agent holds that same door, so work is recursive and parallel: an agent spawns sub-agents; the image runs them and reduces the results.

Security by design

Give an agent specific tools - not all of Python.

Hand a subagent raw Python or a shell and one import os can own the whole system. In zeno a spawned agent reaches only a curated set of functions - the capabilities you grant. What you didn't grant does not exist to it.

(eval '(say "hi")) ; -> "ok" (eval '(slurp "/etc/passwd")) ; -> Unresolved symbol: slurp
Outer
native tools off - the only door in is one eval.
Inner
the grant decides which symbols exist at all.

Secure by construction, not by guardrail - the dangerous call does not exist to the agent. Proven live: tools disabled, one door - the sandbox held.

Layered semantics

Named verbs route themselves.

You say what, not who. A verb clones, routes to the agent best suited to the job, runs it, and returns findings as data.

(review "~/projects/supertool") ;; -> routes to the reviewer agent that does review best, ;; returns findings as EDN data

The caller never names a model or a tool. Routing, cost and orchestration live inside the verb - and improve as the dictionary grows.

The muscle

One verb prepares a whole world for a hard job.

Complex repo? A single verb builds a hermetic Nix sandbox from it, installs the exact tools, cuts several git worktrees for parallel lanes, and gives each a role-scoped agent.

(defverb harden [repo] (let [world (nix-world repo) ; sandbox tools (provision world kit) ; special tools lanes (worktrees repo 3)] ; worktrees (pmap #(run-agent {:cwd % :world world :role :sec-remediation}) lanes))) ; -> parallel PRs, test-gated

Every result returns behind a reproducible test-gate - the whole setup is code, so it is reused, versioned, and rolled back by generation.

The mechanism

Solve once. Replay for free.

The expensive model solves a new shape of task one time. The solution is saved as a verb in the living dictionary.

;; learned once, then replayed as plain code (defverb triage [finding] (-> finding classify verify route))

Every similar task after that replays as code - with ~zero LLM tokens. Works on any stream with repeating structure.

Governance

It grows a vocabulary, not power.

Layer 0 - a small, audited set of effectful primitives. Human-gated. Layer 1+ - the dictionary: pure compositions the system grows itself. A new verb can never exceed the power beneath it.

Tests are the immune system: every new skill ships with an executable test, run by code - not AI - before it persists. Two-layer rollback: dictionary snapshots + Nix generations.

This is the layer where self-improving agents usually die. Here it's native.

Where the approach wins

High volume, repeating - with a hard verifier.

Where those two meet, compounding drives cost down and the code-gate gives trust pure-LLM can't.

CVE / dependency patchinggate: tests pass in a Nix build
Code migration across N servicesgate: each service still builds & tests
SAST / DAST finding triagegate: fix reproduces the known-good result
Alert triage + remediationgate: the runbook is code, not a guess
IaC drift remediationgate: terraform plan / dry-run
CI failure auto-fixgate: the pipeline goes green
